# Weekly Report Platform（轻量周报与智能月报平台）

一个面向研发团队与业务小组的**轻量级周报协作与 AI 月报智能提炼平台**。

无需安装配置复杂的 MySQL、PostgreSQL 数据库，**开箱即用**。自带防并发冲刷排队锁与断电防损坏写入机制，支持一键无损导出排版精美的 Word/Excel 汇报文档。

---

## 💡 为什么做这个项目？

很多团队在日常周报和月报管理中经常遇到这些烦恼：
1. **周五大家都在催周报**，但常用的商业协作工具太重、配置繁琐、甚至还要收费；
2. **月末主管写月报极其痛苦**，需要在群里翻几十份周报，逐条复制粘贴、重新归类、整理排版，耗费大半天时间；
3. **多人周五同时提交容易互相覆盖**，或者因断电、崩溃导致文件损坏丢数据；
4. **传统大模型提炼月报“套话连篇”**，满篇都是“赋能、深耕、砥砺前行”等虚词，完全没法直接作为正式公文汇报。

这个平台就是为了解决这些真实痛点而打造的——**干净、轻量、好看、实用**。

## ✨ 核心特性

- 🚀 **零数据库门槛，开箱即用**：采用高性能本地 JSON 持久化，无需安装任何数据库软件，拉下代码安装依赖即可运行。
- 🛡️ **多人并发安全保护**：
  - **写入排队锁**：周五下班前全员集中点击保存时，服务端自动按毫秒级排队串行写入，彻底杜绝数据互相冲刷覆盖。
  - **军工级原子落盘**：基于操作系统内核 `renameSync` 实现临时文件原子替换，防止写途中断电蓝屏导致文件截断损坏。
  - **协作冲突防覆盖（Confluence 风格）**：同一篇周报若被不同设备或窗口同时编辑，后保存者会被友好拦截，并提供“一键复制草稿”、“拉取最新”和“强制覆盖”选项，绝不丢字。
- 🤖 **AI 月报深度提炼（基于 Dify 工作流）**：
  - 配套提供经过实战打磨的 Dify 提示词工程与数据清洗工作流（`dify/monthly_report_workflow.yml`）；
  - **反幻觉、去 AI 腔调**：严禁无意义抒情与空话，纯基于真实周报事实动态聚类提炼，生成四段式公文规范月报；
  - **无 Dify 兜底保底**：即使完全没有配置 Dify 或断网，内置的本地规则引擎依然能自动聚合周报生成月报大纲，绝不宕机。
- 📊 **无损格式导出**：支持纯前端一键导出排版工整规范的 Word（`.docx`）公文月报，以及 Excel（`.xlsx`）全员周报明细汇总表。
- 📅 **中国法定节假日感知**：内置法定节假日与调休补班算法，自动计算每周实际工作天数。
- 🎨 **极简商务质感**：基于 IBM Carbon 工业化设计规范，配备事项上移/下移排序、大纲浮动导航、响应式适配。

## 🛠️ 技术栈

- **全栈框架**：Next.js 16 (App Router)
- **前端视图**：React 19 + TypeScript 5
- **UI 样式**：Tailwind CSS v4（IBM Carbon 商务设计风格）
- **动效组件**：Framer Motion + Lucide React
- **文档引擎**：docx、xlsx、chinese-workday
- **AI 编排**：Dify Workflow（兼容 DeepSeek / Qwen / OpenAI 等各类主流大模型）

## 🏃 快速启动

### 环境要求
- Node.js 18.18+ 或更高版本

### 方式一：命令行启动（macOS / Linux / Windows 通用）

1. **克隆代码并进入目录**：
   ```bash
   git clone https://github.com/your-username/weekly-report-platform.git
   cd weekly-report-platform
   ```

2. **安装依赖**：
   ```bash
   npm install
   ```

3. **启动开发服务**：
   ```bash
   npm run dev
   ```
   打开浏览器访问 [http://localhost:3000](http://localhost:3000) 即可开始使用！

4. **生产构建与运行**：
   ```bash
   npm run build
   npm run start
   ```

### 方式二：Windows 笔记本双击一键运行

项目根目录已为您准备好实用的批处理脚本：
- **`start.bat`**：启动服务（自动检查并释放被占用的 3000 端口，并打印局域网内网 IP，方便同事访问）；
- **`stop.bat`**：一键安全关闭服务（彻底杀死后台 Node 进程，释放端口）；
- **`start_silent.vbs`**：后台无黑框静默运行（适合开机自启或常驻后台）。

## 🤖 如何使用 AI 月报功能？（手把手接入 Dify）

本系统支持通过开源 LLM 编排平台 **Dify** 进行月报的智能提炼。

> **提示**：如果您暂时没有部署 Dify，系统自带的“本地规则引擎”依然可以正常汇总周报！接入 Dify 则可以让月报具备大模型智能总结、动态聚类与润色能力。

### 详细接入步骤：

#### 步骤 1：准备 Dify
你可以使用自己用 Docker 私有化部署的 Dify，或者使用 Dify 云端社区版（https://dify.ai）。

#### 步骤 2：导入工作流模板
1. 登录 Dify 控制台，点击 **“工作室”** -> **“创建空白应用”**；
2. 类型选择 **“工作流（Workflow）”**，应用名称可填 `部门月报智能提炼`，点击创建；
3. 进入画布页面后，点击右上角的 **“...”**（更多菜单），选择 **“DSL 导入”** 或 **“导入 DSL”**；
4. 选择本项目根目录下的 **`dify/monthly_report_workflow.yml`** 文件并确认导入。

#### 步骤 3：配置并发布大模型
1. 导入后画布会自动生成包含输入、清洗、大模型提炼、输出的完整节点链路；
2. 点击画布中的 **“LLM 智能月报深度提炼”** 节点；
3. 在右侧模型选择下拉框中，选择你已经添加的大模型（推荐使用 **DeepSeek-V3**、**Qwen-2.5** 或 **GPT-4o**，公文提炼效果最佳）；
4. 确认无误后，点击右上角蓝色的 **“发布”** 按钮。

#### 步骤 4：生成 API 密钥
1. 在当前 Dify 工作流左侧导航栏中，点击 **“访问 API”**；
2. 点击右上角 **“API 密钥”** -> **“创建新密钥”**；
3. 复制生成的密钥字符串（格式类似 `app-xxxxxxxxxxxxxxxxxxxxxxxx`）。

#### 步骤 5：在周报平台中配置密钥
1. 将项目根目录下的 `.env.example` 复制一份并重命名为 `.env.local`：
   ```bash
   cp .env.example .env.local
   ```
2. 打开 `.env.local`，填入您的 Dify 地址与刚才生成的 API Key：
   ```env
   DIFY_API_BASE_URL=http://localhost/v1      # 你的 Dify 服务地址（若是官方云平台则为 https://api.dify.ai/v1）
   DIFY_API_KEY=app-xxxxxxxxxxxxxxxxxxxxxxxx  # 你刚才生成的 API Key
   ```
3. 重启本系统服务。进入系统点击顶部 **“月报中心”** -> **“生成部门月报”**，即可体验全自动公文提炼！

## 📂 项目结构说明

```text
weekly-report-platform/
 ├── dify/                          # 配套 Dify 工作流 DSL 导入模板
 │    └── monthly_report_workflow.yml
 ├── data/                          # 本地数据持久化目录（单文件结构，零外部DB）
 │    ├── members.json              # 团队成员名单（已内置脱敏示例数据）
 │    ├── reports.json              # 全员周报数据（已内置脱敏示例数据）
 │    ├── holidays.json             # 中国法定节假日与调休补班配置
 │    └── monthly_reports.json      # 月报归档记录
 ├── public/                        # 静态资源
 ├── src/
 │    ├── app/
 │    │    ├── api/                 # 后端 API 路由（周报、月报、节假日、AI流式保活）
 │    │    ├── edit/                # 周报编辑页（大纲导航、事项上下移、Confluence防冲突）
 │    │    ├── monthly/             # 月报中心（AI提炼、板块编辑、Word/Excel导出）
 │    │    ├── report/[memberId]/   # 个人周报历史明细查看
 │    │    └── page.tsx             # 首页（卡片视图 / 汇总表格双视图切换）
 │    ├── components/               # 现代化 UI 组件库（IBM Carbon 设计风格）
 │    └── lib/
 │         ├── db.ts                # 底层文件排队锁（Mutex Queue）与原子写入落盘
 │         ├── exportMonthly.ts     # Word/Excel 无损文档生成导出器
 │         └── week.ts              # 周期推算与日历算法
 ├── .env.example                   # 环境变量配置示例模板
 ├── start.bat                      # Windows 启动脚本（含端口占用自动释放）
 ├── stop.bat                       # Windows 一键关闭脚本
 └── package.json
```

## 🔒 隐私与私有化保障

- **数据绝对自控**：所有周报数据全部以标准 JSON 格式保存在您本地或私有服务器的 `data/` 目录中，不依赖任何第三方云端商业数据库。
- **杜绝外泄**：若配合本地私有化部署的 Ollama / vLLM 与本地 Dify，整个“周报撰写 - 存储 - AI 月报提炼”链路可在**100% 物理断网的局域网**内安全闭环运行，完全满足企业对数据安全的严格要求。
